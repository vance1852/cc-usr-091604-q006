# 体育场地服务

体育中心场地运营服务的 Python 实现（标准库，无第三方依赖）。

覆盖五人制足球场周末开放场景：登记场地分区与层级、可承载项目与容量、
周期性维护窗口（可跨午夜）、临时封闭发布/提前结束、预约申请→支付回调→
运营审核→带版本确认单→改期/取消退款的完整流程，并提供日历、冲突解释、
替代场地建议与审计（决策来源）接口。

## 设计要点

- **时段模型**：统一半开区间 `[start, end)`，跨午夜时段无需特殊拆分。
- **分区占用关系**：分区支持 `parent_id` 形成层级。上级分区（整场）与任一下级
  分区（半场）互相占用；同级子分区可同时使用；冲突解释会说明联动关系。
- **维护窗口**：按“周几 + 开始时刻 + 时长（分钟）”登记，时长跨日自动展开为
  具体实例，如周六 22:00 / 480 分钟 → 周日 06:00。
- **缓冲清场**：每个分区配置 `buffer_minutes`，双向生效——既有活动结束后的缓冲
  阻挡下一场，新活动自身的缓冲也不得侵入后续封闭/维护。
- **封闭规则**：封闭期间不得新建预约，待审核预约无法确认；发布封闭时返回受影响
  的已确认/待审核活动。已确认活动只能改期或按规则取消。
- **退款依据**：封闭导致无法履约任意提前期全额；自主取消 ≥48h 全额、24–48h
  半额、<24h 不退；审核前付费取消全额、未支付无退款。每条退款记录保留规则代码、
  比例、金额与文字依据。
- **幂等与重启**：申请 `request_id`、支付流水号、确认操作均幂等；全部状态变更在
  同一把锁内完成并原子落盘（构造时传 `path`），重复回调、重复确认、服务重启都
  不会产生双重占用。
- **替代建议**：`suggest_alternatives` 逐个分区说明容量是否足够、项目是否兼容、
  时段是否空闲，并给出拒绝原因。
- **审计**：所有动作写入只追加的有序审计流水；`decision_sources(start, end)`
  汇总某时间段内预约（含各版本确认单、支付、退款依据）、封闭、推导出的维护实例
  及全部相关决策事件。

## 主要接口（`app/venues.py` 的 `VenueService`）

| 类别 | 方法 |
| --- | --- |
| 登记 | `register_venue` / `register_zone` / `register_maintenance` |
| 封闭 | `publish_closure` / `end_closure` |
| 预约 | `request_booking` / `record_payment` / `confirm_booking` / `reschedule_booking` / `cancel_booking` |
| 查询 | `calendar` / `explain`（冲突解释）/ `suggest_alternatives` / `decision_sources` / `audit` / `get_confirmation` |

## 运行

```bash
python3 -m unittest discover -s tests -v
```

## 目录

- `app/venues.py`：场地资源服务（领域模型、冲突引擎、幂等持久化、审计）
- `tests/test_venue_service.py`：并发抢约、跨午夜维护、取消后再预约、
  重复回调/重复确认/重启幂等、退款阶梯、分区联动等行为测试
- `tests/test_smoke.py`：基础健康检查
